What this battery does

The Witness Posture Battery analyzes a question–answer turn-pair from a legal deposition for the structural properties of how the witness responds under examination — not what they said, but how they showed up. Six sequential calls analyze response quality, process control, credibility and integrity, composure, expertise, and adversarial awareness. Call 7 synthesizes all six lenses into a two-word pattern declaration. Every field carries a signed score (−5 to +5) and a dimension tag (coop, cred, excellent, seasoned, or expert). Scores aggregate per-call, per-dimension, and into a grand total for the pair. The scored JSON file is the primary input to this generator — it contains the full analytical output plus all pre-computed score aggregations.

Call 7
Pattern
Pattern Declaration
A two-word label naming what the witness demonstrated across all six analytical lenses — not a topic label or content summary, but a structural signature of how the witness showed up under examination. Synthesized after all six calls are complete. When read in sequence across hundreds of turn-pairs it reveals the higher-order shape of witness performance across the full deposition. Examples: Composed Deflection, Steady Compliance, Calibrated Evasion, Expert Grounding.
Dimensions
coop Cooperative — facilitates examination, responsive, compliant cred Credible — believable, consistent, grounded in personal knowledge
excellent Excellent — superior performance, stays in scope, defensible seasoned Seasoned — experienced, prepared, familiar with materials
expert Expert — combines technical mastery with communication and composure
Universal Return Format — applies to all standard fields
Answer
The primary boolean assessment for the field. Three possible values: true (condition is present), false (condition is absent), or null (insufficient evidence to assess — the pair does not provide enough signal for this field). Null is not a failure state — it means this field cannot be scored on this pair.
true · false · null
Confidence · Evidence · Reasoning
Three conditional fields that appear only when relevant. Confidence (float 0.0–1.0) is present only when answer is true — it scores how certain the model is in the positive assessment. Evidence (array of 1–3 short verbatim quotes) is present only when confidence is exactly 1.0. Reasoning (1–3 sentences) is present only when answer is false — it explains why the condition is absent. None of these appear when answer is null.
confidence: float 0.0–1.0 · only when answer=true
evidence: 1–3 quotes · only when confidence=1.0
reasoning: 1–3 sentences · only when answer=false
Score · Tags
Score is an integer from −5 to +5 that is always present regardless of the answer value — even when answer is null, score is 0. Tags are the dimension labels assigned to the field at battery design time — they are metadata, not produced by the model. Each field belongs to one or more of the five quality dimensions, and tag scores aggregate across calls to produce dimension totals for the pair.
score: integer −5 to +5 · always present
tags: array of dimension labels · fixed at design time

Comprehensive
Uniquely structured field. The question is first classified as exactly open (invites elaboration, narrative, or opinion) or constrained (calls for a specific fact, yes/no, date, name, or brief confirmation). The classification gates which sub-fields appear. For open questions: complete_and_relevant and excessive_and_uncontrolled. For constrained questions: adds_beyond_scope and stays_within_scope. Each sub-field has answer (true/false/null) and score. A score also appears at the comprehensive level itself.
coop
question_type: "open" | "constrained"
if open → complete_and_relevant + excessive_and_uncontrolled
if constrained → adds_beyond_scope + stays_within_scope
Speculation
Is the witness offering possibilities or assumptions not based on personal knowledge or established facts? Two boolean sub-fields: present (is speculation occurring?) and solicited (was the question asking for it?). No answer/confidence/reasoning wrapper — just present, solicited, and score.

Guessing
Is the witness providing an answer despite not knowing, often without stating uncertainty? Structurally identical to speculation: present, solicited, and score. Distinct from speculation — guessing implies lack of knowledge rather than lack of basis.

Scoring Architecture — how scores aggregate
Field Score
Every field carries a signed integer score (−5 to +5). When answer is null, score is 0 and the field's max is excluded from totals — null fields do not penalize the pair. The score is always present in the JSON regardless of answer state.
score: integer −5 to +5 · 0 when null · always present
Call Total
Per-call totals sum all non-null field scores within the call and compare against the possible maximum (non-null fields × 5). Expressed as score / max / percentage. Calls with many null fields have a lower max — the percentage normalizes for this.
score / max / percentage
max = (non-null fields) × 5
Tag Score
Tag scores aggregate field scores by dimension within each call and across the full pair. A field with multiple tags contributes its score to each tag it belongs to. The pair_tag_totals block shows the cumulative score, max, and percentage for each of the five quality dimensions across all six calls — revealing which dimensions the witness performed strongest and weakest on for this pair.
per-call: tag_scores per call
pair-level: pair_tag_totals across all calls
dimensions: coop · cred · excellent · seasoned · expert
Grand Total
The single pair-level composite score: sum of all non-null field scores across all six calls, compared against the total possible maximum. Expressed as score / max / percentage. A score of 50% is the baseline — it means the witness performed adequately across all assessable fields. Scores above 70% indicate strong overall performance; below 30% indicate significant concerns.
grand_total.score / grand_total.max / grand_total.percentage
baseline: 50% · strong: ≥70% · concern: ≤30%
